# 06 · Cloud Agent — ให้ Copilot ทำงานเองบน GitHub

> **ทำต่อเองหลังคลาส** ไม่ได้อยู่ในช่วง hands-on 30 นาที และไม่ใช่โจทย์ coding challenge (ช่วงนั้นใช้ [module 08](../08_coding_challenge/))
> module นี้ต่อกับ [module 07](../07_review_agent/) โดยตรง — PR ที่ได้จากที่นี่ คือ PR ที่ 07 จะเอาไปรีวิว

## เปลี่ยนจากทุก module ก่อนหน้าตรงไหน

module 01–05 ท่านนั่งอยู่หน้า editor แล้ว Copilot ช่วยท่านพิมพ์

module นี้ **ท่านไม่ต้องเปิด editor เลย** — เขียนโจทย์เป็น issue บน GitHub แล้วมอบหมายให้ Copilot
มันจะไปทำงานในเครื่องของมันเอง (ephemeral environment ที่รันบน GitHub Actions) สำรวจ repo แก้โค้ด รันเทสต์
แล้วเปิด pull request กลับมาให้ท่านรีวิว

ระหว่างที่มันทำงาน ท่านไปทำอย่างอื่นได้ นั่นคือประเด็นทั้งหมดของ module นี้

## ก่อนเริ่ม — เช็คสามข้อนี้ก่อน ⚠️

| เช็คอะไร | ถ้าไม่ผ่าน |
|---|---|
| มี Copilot แบบเสียเงิน (แผนไหนก็ได้) | ใช้ไม่ได้ ต้องมี paid plan |
| บัญชีที่ท่านใช้ **ไม่ใช่** Enterprise Managed User (EMU) | fork ไม่ได้ — ดูทางเลือกข้างล่าง |
| ท่านมีสิทธิ์ **write** ใน repo นั้น และ cloud agent ไม่ได้ถูกปิดไว้ | Copilot จะไม่ขึ้นในรายชื่อ assignee |

### ถ้าบัญชีของท่านเป็น Enterprise Managed User

แผน fork ใช้ไม่ได้ ด้วยสองเหตุผลที่แยกจากกัน

1. บัญชี EMU **fork repo นอก enterprise ไม่ได้** และทำอะไรกับ repo สาธารณะข้างนอกไม่ได้เลย ทั้ง push, เปิด issue, เปิด PR, คอมเมนต์ — เห็นได้อย่างเดียว
2. ต่อให้ fork ได้ cloud agent ก็ไม่ทำงานใน **repo ส่วนตัว**ของ EMU เพราะมันรันบน GitHub-hosted runner ซึ่ง repo ส่วนตัวของ EMU ไม่มีให้ใช้

**แต่ module นี้ไม่ได้ตาย** — เอกสารจำกัดข้อห้ามไว้ที่ repo *ส่วนตัว* และระบุว่า runner **ใช้ได้กับ repo ที่ organization เป็นเจ้าของ**

ทางออกคือให้ทีมงานเตรียม repo ไว้ใน **organization ข้างใน enterprise ของท่านเอง** แล้ว seed เนื้อหา lab ลงไป จากนั้นทำ module 06 และ 07 ใน repo นั้นแทน ข้ามขั้นตอน Fork ข้างล่างไปได้เลย

> 💰 repo ในองค์กร EMU เป็น private/internal ซึ่งแปลว่า **module 07 จะเริ่มกิน Actions minutes** ต่างจากแผน fork แบบ public

> ℹ️ การ assign issue ให้ Copilot ยังเป็น **public preview** ปุ่มอาจขยับได้
> ถ้าหน้าจอไม่ตรงกับที่เขียนไว้ บอกทีมงาน หน้าจอของท่านคือของจริง

## ขั้นตอน

### 1. Fork repo นี้ไปบัญชีตัวเอง

กดปุ่ม **Fork** มุมขวาบนของ `palo-it-th/ghcp-adoption-program-hands-on` ครั้งเดียวจบ

ท่านจะได้ `<ชื่อท่าน>/ghcp-adoption-program-hands-on` ที่ท่านมีสิทธิ์เขียน
fork ของ repo สาธารณะเป็นสาธารณะ ซึ่งแปลว่า **ไม่กิน Actions minutes ตอนรีวิวใน module 07**

### 2. เปิด issue บน fork ของท่าน

ไปที่แท็บ **Issues** → **New issue** → คัดลอกโจทย์จาก [`tasks/`](./tasks/) มาวาง

มีสองโจทย์ให้เลือก เลือกอันเดียวพอ

| โจทย์ | ไฟล์ | ทำไมถึงเหมาะกับ agent |
|---|---|---|
| เขียน unit test ให้เครื่องคิดเลข | [`tasks/add-calculator-tests.md`](./tasks/add-calculator-tests.md) | ขอบเขตชัด ตรวจผลได้ ไม่ต้องตัดสินใจเรื่อง design |
| เพิ่มปุ่มเปอร์เซ็นต์ในเครื่องคิดเลข | [`tasks/add-percent-button.md`](./tasks/add-percent-button.md) | feature เล็กที่แตะสามไฟล์ ได้เห็นว่ามันไล่แก้ครบมั้ย |

### 3. มอบหมายให้ Copilot

1. เปิด issue ที่เพิ่งสร้าง
2. แถบขวามือ คลิก **Assignees**
3. เลือก **Copilot** จากรายชื่อ
4. จะมีกล่องขึ้นมา ช่อง **Optional prompt** ใส่คำสั่งเพิ่มได้ เช่น "ห้ามแก้ไฟล์นอกโฟลเดอร์ calculator"
5. ยืนยัน

Copilot จะเริ่มทำงานทันที และ**ขอให้ท่านเป็น reviewer เองเมื่อมันเสร็จ**

> ⚠️ Copilot เห็นเฉพาะ title, description, คอมเมนต์ที่มีอยู่ ณ ตอนที่ท่าน assign และ optional prompt
> **คอมเมนต์ที่เติมทีหลังใน issue มันจะไม่เห็น** ถ้ามีอะไรจะบอกเพิ่ม ให้ไปคอมเมนต์ใน PR ที่มันเปิด

### 4. ไปทำอย่างอื่นระหว่างรอ

มันใช้เวลาหลายนาที ไม่ต้องนั่งเฝ้า กลับไปทำ module 05 ต่อ หรือเริ่มอ่าน module 07 ไว้ก่อน

### 5. กลับมาอ่านสิ่งที่มันทำ

พอ PR ขึ้นแล้ว อย่าเพิ่งรีบดู diff ให้ดูสามอย่างนี้ก่อน

- **session log** — มันสำรวจไฟล์ไหนบ้าง ตัดสินใจอะไร ตรงนี้คือสิ่งที่ IDE ไม่เคยให้ท่านเห็น
- **commit ทีละอัน** — มันแบ่งงานเป็นขั้นยังไง
- **คำอธิบาย PR** — มันเข้าใจโจทย์ตรงกับที่ท่านคิดมั้ย

แล้วค่อยอ่าน diff

## คำถามสำหรับแชร์

- โจทย์ที่ท่านเขียน ชัดพอมั้ย หรือมันเดาผิดตรงไหน
- ถ้าให้เขียนใหม่ จะเพิ่มอะไรใน issue
- งานแบบไหนในทีมท่านที่ควรส่งให้ agent ทำ และแบบไหนที่ไม่ควร
